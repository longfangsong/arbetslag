# 形状是状态

一份工作流的图 = 形状 + 每个节点的私有状态与邮箱。形状是有哪些节点、它们是什么、它们怎么连；它不是模板的投影，也不是编译产物，就是图里的结构那一半持久状态，运行时可被任何节点改写。模板因此只被读一次（见下）。

**Status**: accepted；「扇出不在边层」与「`(from, port)` 至多一条边」两条已由 **ADR-0011** 取代（边是订阅，`(from, port)` 可以有多条）；其余各条不变。

## 决定

- **形状 = 节点记录 + 边 + 触发器**（触发器见 ADR-0001），与节点的私有状态、邮箱同在一条快照里。
- **边是三元组** `{ from, to, port }`，端口必填。`(from, port)` 可以有 0..N 条（ADR-0011，取代本文原先的「至多一条」）。自环合法——节点给自己发消息是正当的（例如重试循环）。
- **端口在发送侧**，是节点定义声明的出口类别（声明是 config 的纯函数，同一个定义在不同 config 下可以有不同的端口集，例如 agent 一个工具一个端口）：该节点发出的那个可辨识联合的判别标签。接收侧没有端口——消息带着自己的类型，由节点自己分派。
- **扇出在边层**（**已被 ADR-0011 取代**：沿边发 = 订阅，可以是多个目标；需要顺序、失败、去重的多路分发仍然写一个节点）。原决定是「一个端口最多一个目标，要一路发到多处就写一个节点去做」。
- **改图是唯一的图操作**，新增 / 断线 / 接线 / 回收（以及增删触发器）是它的形式。**改图是一种效果**（`graph.mutate`，ADR-0006）：节点在转移里交出一批操作，之后由回执告诉它结果；`Transition` 没有专门的改图字段。任何节点都能交出它：没有特权节点，没有父子关系，没有 supervisor 通道。
- **一批操作的应用顺序固定**：先全量校验，再新增 → 断线 → 接线 → 回收；整批要么全部生效，要么都不生效。断线在接线之前，所以"把一个端口改接到别处"可以写在同一批里。
- **回收连带删边**：被回收的节点同时从所有边里消失，不留悬空边。
- **节点 id 由创建者给**（模板里的键、改图时写死的字符串），不透明；内核只校验"活节点里唯一"，回收之后不禁止复用。
- **投递必须有路**：图内发送没有对应的边 → 丢弃，并在转移日志里记一条。发送时显式给出目标 id 的不经过边（ADR-0005）。触发器的外部投递沿从触发器出发的边走（边的起点可以是触发器，ADR-0001）；effect 结果不经过边。
- **改图非法不是停住**：整批不应用，回执的 `result` 是失败（带违规列表），与别的效果失败一样是普通结果（ADR-0008）。只有**载入**时发现形状违反不变量（快照被写坏、或部署后定义变了接不上）才停住。
- **模板只用于实例化**：实例化之后，工作流的形状和状态与模板无关；改模板只影响今后新建的工作流。要让已有工作流跟上模板，只能走显式迁移（未设计）；在此之前唯一办法是新建一份。
- **跨工作流投递不是图操作**：往另一个工作流投一条消息不改变任何一张形状，所以它不是形状改写的一种（ADR-0001 的 `forward` 因此不是结构字段）。

## 为什么

- **模板为什么只读一次**：实例化之后每份工作流都会各自 spawn / connect / retire，长出不同形状；"模板持续有权威"要求框架在运行中的图上做自动改写，那是一次显式迁移，不该藏在"改文件"里。
- **改图为什么是效果**：它和其它效果一样是"一次性请求，结果以回执回来"，于是 `Transition` 只有 `state`、`sends`、`effects` 三样，改图不在转移里变得特殊。一批操作放在**同一个**效果里，是因为不同效果之间没有顺序保证（执行器可以并发），而改图的顺序有语义（先新增才能接线）。
- **改图为什么对图是 exactly-once**：执行器应用改动、删在飞记录、给 origin 追加回执，是同一次 CAS 写（ADR-0006 的一次性令牌）；重试不会重复新增节点。
- **形状为什么要进快照**：运行时会改图，改完必须能原样重建；如果形状只是模板的投影，新增和回收就没有地方记。
- **端口为什么在发送侧、为什么单值**：节点定义必须与图无关——同一份 `builtin.agent` 要用在任意模板里，它只能说"这是给工具的""这是给用户的"，说不出"给 n3"。单值则是因为"一个出口通到两个地方"在语义上是广播，而广播的正确做法是一个节点显式地做；把广播做成边的默认语义，等于让顺序、失败与去重无处表达。
- **投递无路为什么是丢弃而不是报错**：没有边等于没人订阅。把"没人订阅"变成失败，会逼内核区分"作者故意不接"和"作者忘了接"，而这个区别在运行时并不存在。
- **id 为什么允许复用**：回收时内核连带删边、等待被打断，回收之后没有活的引用还能指向旧 id；禁止复用要付一张随回收次数增长的墓碑表，而单条快照有 2 MB 上限。

## 代价（接受）

- "忘了接线"会静默丢消息，只能从转移日志里发现。
- 边是运行时数据，所以"通信必须有边"只能是运行时不变量，不能在类型层保证；类型层能保证的是端口名与每个端口的载荷。
- 想连多个工具（或任何多点投递）的节点需要一个中间节点。
- **新增的节点要等回执才能用**：同一条转移里没法给刚交出新增请求的节点发消息，因为它那时还不存在。
- **非法改图只是一条失败回执**：节点若没处理它（漏接回执表现为静止，ADR-0006），这次改图就悄悄没发生；ADR-0002 原先"宁可停住，也不静默改图"的保证放宽成了"失败是显式结果，是否处理由节点负责"。

## Retired designs（不要重提）

- **数组位置即身份**、`connections: [[i, j]]`：改一下声明顺序就悄悄改了接线。
- **端口在接收侧**（像 HTTP 路由）：发送方仍然需要一种不依赖目标身份的说法，所以它只是补强，不能单独存在。
- ~~**边层扇出**~~：**已解除**（ADR-0011）——广播在编排里是结构，不是行为。
- **无名边（没有端口名的边）**：消息一律带类别（ADR-0005），没有名字的路没有消息可走；曾经的 `(from, to)` 至多一条规则随之取消。
- **父子关系 / 新增节点隐含接线 / supervisor 端口**：图内所有节点平等。
- **墓碑表 / 禁止 id 复用**。
- **改模板 → 已存在的工作流自动跟着变**：需要自动改写运行中的图，且与 spawn 出来的形状冲突。
- **模板里写按会话切分的规则**：切分粒度由实例化方决定，模板不表态（ADR-0001）。
- **改图作为 `Transition` 的字段、或 step 同步返回改图操作**：改图是效果；同步应用要求内核在转移里改形状，并让"消息发送在形状落定之后才解析"成为特例。
- **一批改图拆成多个独立效果**：它们之间没有顺序保证。
