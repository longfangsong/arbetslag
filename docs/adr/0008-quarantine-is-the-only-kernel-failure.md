# 隔离是内核唯一的失败出口

内核只有一种失败：无法继续。出现时当前转移整条不应用，整份工作流停住，快照原样保留，等人处理。其它一切失败——效果失败、坏消息、预算耗尽、触发器起不来——都不是隔离，而是普通结果。

**Status**: accepted

## 决定

- **隔离的触发条件（封闭清单）**：step 抛错；state 或 config 不符合 schema；迁移失败；节点定义未知；记录版本比在场定义新；改图非法；触发器声明非法（ADR-0001）；效果种类未知或 `input` 不合规（ADR-0006）；节点发出 `@` 前缀端口（ADR-0005）；快照超限。
- **隔离整份工作流**，不是单个节点：图内所有节点平等，没有节点级判死，也没有 supervisor（ADR-0002）。
- **失败转移不提交**：触发隔离的那条转移整条不应用；触发它的消息仍在邮箱队首。
- **隔离带结构化载荷**：快照里记 `{ code, node?, detail, at }`。`code` 是内核定义的封闭枚举，取值对应上面的触发条件；`detail` 是自由文本，不含堆栈。具体字段名与枚举取值不钉死。
- **解除只有一个动作 `release(id)`**：清掉隔离标记，仅此而已。内核不提供修改快照的手术式修复；修复靠改部署（修好的节点定义、迁移）。`release` 之后下一次 `run` 会重新处理队首那条消息。
- **隔离期间**：触发器的外部投递被拒绝，调用方得到明确的"已隔离"，由触发器实现方决定重试或丢弃；**效果回执被接受并追加进邮箱，但不触发 `run`**，`release` 之后照常处理。
- **不是隔离的失败**：效果失败（`@effect.end` body 的一种形状）、业务上的坏消息（一条普通消息）、步数预算耗尽（ADR-0007）、触发器声明合法但起不来（ADR-0001）。

## 为什么

- **为什么整份隔离**：宁可停住，也不静默丢节点或静默改图。部分隔离需要内核判断"这个节点坏了、图的其余部分还对"，而这个判断恰恰是内核无法做的。
- **为什么封闭枚举**：宿主要能按原因写处理逻辑（例如 `version_ahead` 是回滚部署，`snapshot_too_large` 需要人介入），匹配字符串做不到这一点。
- **为什么只有 `release`**：修快照等于绕过 schema 校验，让"坏状态绝不进快照"（ADR-0004）失去保证；修部署则每一步都经过正常路径。
- **为什么回执要接受**：回执是一次性令牌（ADR-0006），隔离时拒绝它，执行器就丢了结果，图永远收不到，也无法恢复。隔离的含义是"内核拒绝再推进"，不是"拒绝听见"。

## 代价（接受）

- 毒消息（每次都让 step 抛错）会在 `release` 之后立刻再次隔离。这是显式可见的，不会被吞掉。
- 隔离期间邮箱会持续接收回执，受快照上限约束；撞限之后继续到达的回执无法再被接受，会丢失。
- 一份工作流里一个节点出错就停住全部节点，包括与出错节点无关的部分。

## Retired designs（不要重提）

- **supervisor、`@node.failed`、节点级判死。**
- **部分隔离**（只停出错的节点）。
- **修改快照的手术式修复动作。**
- **隔离期间拒绝一切投递**（包括效果回执）。

## 反转条件

- 如果隔离期间回执丢失成为实际问题，再讨论为回执提供独立于邮箱的暂存位置。
- 如果"整份隔离"在多节点大图里误伤频繁，再讨论子图隔离，前提是内核能判定子图边界。
