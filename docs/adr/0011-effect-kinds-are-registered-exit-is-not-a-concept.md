# 效果种类要注册，"出口"不是概念

效果的 `kind` 与触发器的 `kind` 同构：宿主把它的定义（名字、input schema、回执 body schema）注入给内核，内核校验节点交出的效果，从不执行它。"出口节点"没有任何内核层面的特殊性，它只是一个 step 里会交出某类效果的普通节点，不进术语表。

**Status**: accepted

## 决定

- **效果种类由宿主注入**：每个 kind 有名字、`input` schema、回执 `body` schema，与节点定义、触发器种类同属注入给内核的注册表（ADR-0007、ADR-0010）。
- **内核在 step 返回时校验 `effects`**：未知 kind、`input` 不合规 → step 返回非法 → **隔离**（与改图非法同级）。内核仍然不执行任何效果。
- **没有"出口节点"这个概念**：出口与非出口在内核眼里没有区别，没有任何规则需要区分它们。它作为一种节点定义写法，随内置节点一起在 agents 包里出现。
- **出口型效果的回执**照 ADR-0008：一定有，body 可为空。
- **未识别的消息类别由 step 显式处理**：内核不提供"默认丢弃"。节点定义里写一个 `default: return { state }` 就是显式忽略；这同样适用于出口节点接住的空 `@effect.end`。

## 为什么

- **为什么不给出口单独的类别**：它没有邮箱、状态、推进之外的行为差异。给它起名字，就得回答"内核怎么区分"，而找不到任何答案。
- **为什么 kind 要注册**：校验 `input` 是纯检查、不碰外界，与 state schema 同类；让非法效果在交出那一刻就被拦下，而不是留到执行器里才炸、且在快照里留下一条永远回不来的在飞记录。执行必须留在宿主，因为 Node 与 Workers 的执行方式不同（ADR-0006）。
- **为什么不兜底丢弃未识别类别**：静默丢弃会掩盖"消息被发到错误的节点"。入站形状归应用（ADR-0009），内核无从判断哪些该忽略。

## 代价（接受）

- 每个效果种类都要先在宿主里注册 schema，才能被节点使用。
- 节点定义里的 step 必须显式写 `default`；漏写时未识别的类别会走到 TypeScript 的穷尽检查或运行时错误，而不是被悄悄吃掉。

## Retired designs（不要重提）

- **术语"出口节点"**，以及任何让内核区分出口与非出口的规则。
- **内核对效果 kind 一无所知**：它至少要认名字与 schema，才能在交出时拦下非法效果。
- **内核提供默认丢弃**未识别的消息类别。

## 反转条件

- 如果大量节点都在重复同一份"发 effect + 忽略回执"的样板，就在 agents 包里提供一个 helper，而不是把出口提成内核概念。
